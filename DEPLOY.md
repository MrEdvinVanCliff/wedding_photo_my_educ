# Запуск у межах безкоштовних квот: Render + Supabase + Cloudflare R2

Сайт і FastAPI працюють на Render Free; публікації та лайки — у PostgreSQL
Supabase Free; оригінали й WebP-копії — у Cloudflare R2 Standard. MacBook після
публікації не потрібен. Старі дані відсутні: нова база буде порожньою.

## 1. Supabase

1. У https://supabase.com/dashboard створіть окремий проєкт у Free-організації.
   Збережіть пароль бази у своєму менеджері паролів. Виберіть європейський регіон.
2. У **Connect → Session pooler** скопіюйте PostgreSQL connection string
   (порт **5432**, користувач `postgres.PROJECT_REF`). Підставте пароль;
   спеціальні символи пароля в URL мають бути percent-encoded.
   Саме Session pooler підтримує IPv4; не беріть direct IPv6 connection.
Таблиці автоматично створюються в окремій схемі `wedding`, поза стандартною
`public` схемою Data API. Supabase Storage та service_role key більше не потрібні.

## 2. Cloudflare R2

1. У https://dash.cloudflare.com відкрийте **R2 Object Storage** та активуйте R2.
   Cloudflare може вимагати платіжний метод та підтвердження підписки.
   Активацію й платіжні поля власник акаунта заповнює самостійно.
2. Створіть окремий bucket **wedding-photos**, клас **Standard**, звичайне
   розміщення (не спеціальна EU jurisdiction), за бажанням європейська location hint.
   Залиште bucket приватним. `r2.dev`, публічний домен та CORS для поточних
   `<img>` і звичайного завантаження за посиланням не потрібні.
3. Створіть R2 API credentials з дозволом **Object Read & Write**, обмеженим
   цим bucket. Збережіть **Access Key ID** і **Secret Access Key** у Render.
   Звичайний Cloudflare API token не замінює ці S3 credentials.
4. Скопіюйте **Account ID** — 32 шістнадцяткові символи.

Сервер перевіряє й обробляє фото, надсилає оригінал і дві WebP-копії до R2.
Галерея отримує сталі `/media/...` адреси: сервер перевіряє запис у БД і
перенаправляє браузер на підписане R2-посилання, чинне одну годину.
Файли йдуть із R2 без проксіювання їхнього вмісту через Render.
При пізньому відкритті фото сервер видає свіже посилання.

Галерея залишається відкритою для перегляду й додавання фото без реєстрації.
Приватний bucket не означає приватну галерею: кожен із адресою сайту може
отримати посилання на фото, включно з оригіналами з метаданими.
Секретні ключі не потрапляють у HTML/JavaScript або GitHub.

## 3. GitHub

Створіть приватний репозиторій і завантажте файли застосунку:

- `main.py`, `cloud.py`, `requirements.txt`, `render.yaml`;
- `index.html`, `style.css`, `script.js`, папку `assets/`;
- за бажанням — `tests/`, `requirements-dev.txt`, документацію та `.gitignore`.

Не завантажуйте `.venv/`, `.env`, `data/`, `uploads/` або секретні ключі.
Папка `photo/` — попередні матеріали, не база публікацій; застосунок її не обслуговує.

## 4. Render

1. У https://dashboard.render.com виберіть **New → Blueprint**, підключіть
   підготовлений репозиторій і використайте `render.yaml`.
2. Перевірте, що сервіс має план **Free**. Blueprint не створює платних дисків
   або Render Postgres.
3. Введіть секретні значення у формі Render:

| Змінна | Значення |
| --- | --- |
| `DATABASE_URL` | Connection string із Supabase Session pooler |
| `R2_ACCOUNT_ID` | Cloudflare Account ID |
| `R2_ACCESS_KEY_ID` | R2 Access Key ID |
| `R2_SECRET_ACCESS_KEY` | R2 Secret Access Key |

Решта значень уже в Blueprint: `WEDDING_BACKEND=cloud`,
`R2_BUCKET=wedding-photos`, тимчасовий каталог `/tmp/wedding`.
Файл `.env.example` є довідкою: застосунок автоматично `.env` не читає.

4. Запустіть deployment. У разі помилки перевірте pooler URL, пароль та bucket.
   Без повної хмарної конфігурації сервер не запускається; він не підмінює БД
   тимчасовою SQLite.
5. Відкрийте видану Render HTTPS-адресу `https://…onrender.com`.
   Власний домен для роботи не потрібен.

## Обробка фотографій OpenAI

У Render → wedding-gallery → Environment додайте **OPENAI_API_KEY** зі свого
OpenAI API project. Не додавайте ключ у GitHub або JavaScript. Поповнення балансу
не додає ключ автоматично. `OPENAI_IMAGE_MODEL=gpt-image-2.5-sunburst` задано у
Blueprint; за відсутності змінної застосунок використовує цю ж модель.
Ключ не є обов’язковим для звичайної галереї: без нього обробка покаже зрозумілу помилку.

На Render потрібен файл `image_edit.py` та оновлені `main.py`, `script.js`,
`index.html`, `requirements.txt`. У Environment після додавання ключа збережіть
зміни з перезапуском сервісу. Перевірте доступ проєкту OpenAI до Images API.

У розширеному режимі натисніть «обробити», дочекайтеся нового прев’ю, потім
«завантажити». OpenAI отримує зменшену WebP-копію без EXIF. До публікації результат
живе у вкладці браузера; після публікації — в R2. Запит може тривати кілька хвилин;
тайм-аут звернення до OpenAI — 240 секунд, автоматичні повтори вимкнені.
Результат може бути втрачено при перезавантаженні сторінки або перезапуску Render.
Нова спроба після мережевої помилки може оплачуватися повторно.

Endpoint обробки відкритий так само, як завантаження галереї. Одна одночасна
обробка на процес запобігає перевантаженню, але не є бюджетним обмеженням.
Контролюйте витрати й доступ у своєму OpenAI project.

Інтеграція: [офіційна документація OpenAI Images API](https://developers.openai.com/api/docs/guides/image-generation).

## 5. Перевірка після публікації

1. `/healthz` повертає `{"status":"ok"}`; `/api/posts` — порожній список.
2. Додайте одну тестову публікацію з кількома фото, поставте лайк і скачайте оригінал.
3. Перезапустіть сервіс у Render. Публікація й фото мають залишитися.
4. Вимкніть сервер на MacBook, відкрийте HTTPS-адресу телефоном через мобільну мережу.
5. Перевірте використання R2 у Cloudflare; видалення сервісу Render не створює
   резервної копії й не видаляє фото R2 або записи Supabase.

## Безкоштовні обмеження

Перевірено 30 вересня 2026 року; тарифи можуть змінитися.

- Render Free засинає після 15 хвилин без запитів. Наступне відкриття може
  зайняти приблизно хвилину. Доступно 750 instance-hours на місяць для workspace.
  Локальний диск стирається, тому використовується лише для тимчасової обробки фото.
- Supabase Free: 500 MB БД; квота Supabase Storage не використовується.
- R2 Standard: 10 GB-month сховища, 1 млн операцій Class A та 10 млн Class B
  щомісяця безкоштовно; вихідний трафік безкоштовний. Це квоти на акаунт,
  спільні з іншими bucket. Понад них діє оплата за використання.
  Сховище понад квоту коштує $0.015/GB-month; операції оплачуються окремо.
  Безкоштовні квоти не поширюються на Infrequent Access.
- Оригінал та дві WebP-копії разом витрачають квоту. За середніх 5 MB на фото
  з копіями 10 GB — приблизно 2000 фото. Це оцінка, не ліміт кількості.
  Стежте за R2 usage та billing: застосунок не встановлює жорсткого обмеження
  витрат Cloudflare і не блокує автоматично завантаження після 10 GB.
- Supabase може призупинити проєкт після 7 днів низької активності;
  відновлення виконується в Dashboard. Не створюйте штучних запитів для обходу лімітів.
- Безкоштовний тариф не гарантує безперервну роботу. Перед весіллям перевірте
  доступність і вільне місце. Render також обмежує навантаження й може
  призупинити Free-сервіс за надмірного вихідного трафіку до R2/БД.
- Зберігайте окремі резервні копії БД та об'єктів Storage. Перенесення в хмару
  саме по собі не є резервним копіюванням.
