# Весільний альбом — локальна галерея

Наявні HTML, CSS та JavaScript обслуговує FastAPI. Публікації й лайки зберігаються в SQLite, фотографії — на MacBook. Збирання фронтенду та cloud storage не потрібні.

## Перший запуск на MacBook

У Terminal:

```sh
cd /Users/user/Desktop/wedding/testWeddingWeb
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
uvicorn main:app --host 0.0.0.0 --port 8000 --reload
```

Залежності вже встановлено в `.venv` цього проєкту. Для наступних запусків достатньо активувати середовище й виконати команду `uvicorn`.

На MacBook: [http://localhost:8000](http://localhost:8000).

На телефоні в тій самій Wi-Fi мережі: `http://LOCAL_MAC_IP:8000`. IP можна перевірити командою:

```sh
ipconfig getifaddr en0
```

Під час реалізації адреса була **http://192.168.4.111:8000**. Вона може змінитися після перепідключення до Wi-Fi. `0.0.0.0` використовується лише в команді сервера; у браузері телефона потрібна IP-адреса MacBook. MacBook має бути увімкнений, Terminal із сервером — відкритий. Якщо macOS запитує доступ Python до вхідних підключень, дозвольте його для цього локального тесту. Зупинка сервера: `Ctrl+C`.

Для галереї слід запускати саме FastAPI, а не `python -m http.server`: звичайний статичний сервер не має API.

## Як перевірити з телефона

1. Натиснути «додати фото», залишити «звичайний» режим.
2. Вибрати від 1 до 12 фотографій, зокрема вертикальні й горизонтальні.
3. Ввести ім’я або ввімкнути «Додати анонімно»; коментар необов’язковий.
4. Натиснути «завантажити»: одна відправка створює одну картку.
5. Гортати кілька фото пальцем; dots показують поточне фото, висота картки змінюється за його пропорціями.
6. Натиснути серце: повторне натискання прибирає лайк.
7. Оновити сторінку або перезапустити FastAPI: публікації, фото й лайки зберігаються.

Галерея має дві незалежні колонки. Фото не обрізаються; у картки без коментаря немає елемента коментаря, а довгий текст займає один рядок із трикрапкою. Для одного фото не створюються карусель і dots. На комп’ютері також можна використовувати dots і клавіші ← / → у каруселі.

Збережено наявний «розширений» режим з одним фото та вибором стилю. У цьому MVP стиль записується як налаштування публікації, але не змінює зображення; форма це пояснює.

## Де лежать дані

- `data/wedding.sqlite3` — публікації, порядок фото й лайки; поруч можуть бути службові файли SQLite `-wal` / `-shm`.
- `uploads/` — оригінал кожного завантаженого фото та дві WebP-копії для швидкого перегляду. Поворот із метаданих телефона застосовується до копій; співвідношення сторін зберігається.
- `photo/` — попередні статичні матеріали залишено без змін. Вони не імпортуються як вигадані публікації: нова база починається з порожньої галереї.

Ліміти: 12 фото на публікацію, 10 МіБ і 50 мегапікселів на файл. Підтримуються JPG, PNG, WebP, GIF, AVIF, HEIC/HEIF. Для GIF/багатокадрових файлів галерея показує перший кадр, оригінал зберігається. Якщо браузер не показує HEIC-прев’ю, форма використовує заглушку; після завантаження сервер створює звичайне зображення для галереї.

`uploads/` і `data/` не потрапляють у Git. Для резервної копії зупиніть сервер і скопіюйте обидві папки разом. Звичайне оновлення коду або перезапуск їх не очищує.

Device ID зберігається в `localStorage` під ключем `wedding.deviceId`. Лайки записуються на сервері з унікальною парою «публікація + deviceId». Різні браузери, видалення сховища та різні адреси сайту створюють інший ідентифікатор; це локальна MVP-ідентифікація без реєстрації.

## API

| Метод | Шлях | Призначення |
| --- | --- | --- |
| GET | `/api/posts` | Усі публікації, найновіші першими |
| POST | `/api/posts` | Одна публікація з 1–12 файлами |
| POST | `/api/posts/{id}/like` | Перемкнути або встановити стан лайка |

`GET /api/posts` приймає необов’язковий заголовок `X-Device-Id: UUID`, щоб повернути персональний `likedByDevice`.

`POST /api/posts` приймає `multipart/form-data`:

- `photos` — повторюване поле з файлами;
- `authorName` — ім’я, обов’язкове без анонімності;
- `isAnonymous` — `true` / `false`;
- `comment` — необов’язковий текст до 280 символів;
- `submissionId` — необов’язковий UUID; фронтенд передає його для захисту від дублів при повторі запиту;
- `uploadMode` — `standard` або `advanced`; необов’язковий `photoStyle` для розширеного режиму.

Відповідь: `id`, `authorName`, `isAnonymous`, `comment`, `createdAt`, `likesCount`, `likedByDevice`, `photos` та налаштування режиму. Кожне фото має `id`, `url`, `thumbnailUrl`, `originalUrl`, `width`, `height`, `thumbnailWidth`. Файли повертаються в порядку вибору.

Лайк приймає JSON:

```json
{"deviceId": "UUID", "liked": true}
```

`liked: false` прибирає лайк. Якщо `liked` не передано, стан перемикається. Фронтенд передає бажаний стан, тому повторний запит після мережевої помилки не додає другого лайка.

Інтерактивна документація: [http://localhost:8000/docs](http://localhost:8000/docs).

## Перевірки

```sh
source .venv/bin/activate
python -m pip install -r requirements-dev.txt
python -m unittest discover -s tests -v
```

Автоматичні тести використовують окремі тимчасові SQLite та uploads, не зачіпаючи ваші дані. Вони перевіряють групування шести фото, порядок, анонімність, коментар, перезапуск, like/unlike, паралельні лайки, повторний upload, ліміти, пошкоджені файли, EXIF-поворот, HEIC і недоступність приватних файлів через HTTP.

У браузері перевірено завантаження шести фото однією формою, HEIC, відсутність dots/коментаря для одиночного фото, зміну dots при горизонтальному прокручуванні, зміну висоти без обрізання, лайки та refresh. Тестові дані браузерної перевірки ізольовано в `/tmp`; реальна галерея залишається чистою. Окремо перезапущено процес FastAPI та перевірено збереження всіх тестових публікацій і файлів. Фізичний телефон не підключався; для нього наведено сценарій вище.

Реалізація спирається на [FastAPI UploadFile / multipart](https://fastapi.tiangolo.com/tutorial/request-files/), [Pillow ImageOps.exif_transpose](https://pillow.readthedocs.io/en/stable/reference/ImageOps.html) і [Pillow HEIF plugin](https://pillow-heif.readthedocs.io/en/stable/pillow-plugin.html).
